The RedRays preview solution brings SAP vulnerability, ABAP code, BTP, segregation of duties, profile parameter and password security findings into Microsoft Sentinel with analytics rules and a workbook. RedRays exports on a configurable schedule from your existing environment. It does not collect SAP Security Audit Log events or populate ABAPAuditLog. A RedRays license with Microsoft Sentinel integration is required.

Underlying Microsoft Technologies used:

Log Analytics, Logs Ingestion API and DCRs, and Microsoft Entra applications and service principals. Azure ingestion and retention charges apply.

Additional Documentation

📄 Source: RedRays SAP Security Findings/README.md

Bring RedRays SAP security findings into Microsoft Sentinel to review them alongside your other security data. This preview includes findings from Vulnerability Assessment, ABAP Code Security, BTP Security, Segregation of Duties, SAP Profile Parameters and Password Security. Threat Modelling is not included.

RedRays stays in your existing Docker, on-premises or cloud environment and sends findings through the Azure Monitor Logs Ingestion API on a schedule you choose. The solution supports Azure public cloud. You need a RedRays license with Microsoft Sentinel integration; Azure ingestion and retention charges are separate.

This solution covers security assessments. It does not collect SAP Security Audit Log events, populate ABAPAuditLog or activate Microsoft's built-in SAP audit detections.

Set up the integration

The Content Hub package installs a Codeless Connector Framework (CCF) push connector, six analytics rule templates and a workbook template. You deploy the ingestion resources from the connector page and enable the rules after installation. RedRays sends the data. The package does not deploy a RedRays server, Azure Function, VM or polling agent.

  1. Deploy the push connector resources. In Microsoft Sentinel, open Data connectors > RedRays SAP Security Findings and select Deploy. Sentinel creates a data collection endpoint (DCE), a data collection rule (DCR) and the eight RedRays tables, then registers a Microsoft Entra application with a client secret and grants it the Monitoring Metrics Publisher role on the DCR. You need permission to create app registrations and to assign roles on the DCR. Copy the client secret immediately; it is shown only once.
  2. Configure RedRays. In RedRays > Platform Settings > Microsoft Sentinel, enter the tenant ID, application (client) ID, client secret, DCE URI and DCR immutable ID shown on the connector page. Choose the modules and export interval, then save and enable the integration. Keep alertOnBaseline disabled for the first import so you can review the initial findings before creating alerts.
  3. Check delivery. Send a test event, then wait for a scheduled export. Query RedRaysExportHealth_CL for RecordKind == 'HEARTBEAT'. A successful test means Azure accepted the request; the data may take time to appear in queries.
  4. Enable the content you need. In Manage solution, create the workbook and your chosen analytics rules. Review the initial findings first. Set the workbook export health threshold above your export interval, allowing time for ingestion.

Allow outbound HTTPS from RedRays to Microsoft Entra and the data collection endpoint. No inbound connection to RedRays is required. Rotate the application credential in Entra and update it in RedRays before it expires. Keep credentials out of the solution package.
